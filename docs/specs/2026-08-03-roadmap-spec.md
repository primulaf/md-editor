- 版本号升至 1.6.2（`package.json` 与 `manifest.json` 同步，项目校验强制一致）。

### 1.2 单一完整包分发

决定：不再发布 Lite 与 Dependency 包，唯一产物为完整包。

- 产物命名为 `md-editor-<version>.zip`，`SHA256SUMS.txt` 保留（单行记录）。
- `scripts/package-extension.mjs`：只构建一个目录，删除 lite / dependency 分支逻辑。
- `scripts/validate-dist.mjs`：改为校验单包——必须包含 Mermaid 完整分块（≥100）、不含开发文件与嵌套 ZIP、SHA-256 匹配。
- 保留 `mermaid-capability.json` 与 `lib/mermaid/version.json` 探测机制作为安全兜底：依赖缺失或损坏时仍回退显示源码，但不再存在"补装组件"的分发场景。
- `index.html` 中 Mermaid 安装说明对话框改为提示"请重新安装完整版扩展"。
- 同步更新 `README.md`、`AGENTS.md` 与新增的 `docs/releases/v1.6.2.md`。既有发布说明作为历史记录保留，不追溯改写旧版本的产物描述。

验收标准：

- `npm run package` 只生成 1 个 ZIP 与 1 行 SHA-256。
- 单包与旧 Full 包内容一致（除命名），Lite 场景彻底移除。
- 能力探测失败时仍正确回退源码，不阻断 Markdown 渲染。

### 1.3 分支清理

- 已删除本地与远端 `release/1.5`、`release/1.6` 分支；删除前已确认两条分支均完整包含在 master 中，没有独有提交。
- master 作为唯一开发与发布主线，版本发布统一使用 tag。

### 1.4 Storage 泄漏清理

现状：

- `content.js` 写入 `file:<nonce>` / `name:<nonce>`，仅当 `app.js` 成功加载后删除。
- 发送消息失败、标签页中途关闭或跳转失败时键会永久残留。

方案：

- 写入改为单一信封键 `pending:<nonce>`，值为 `{ content, name, ts }`，便于统一清扫。
- `content.js` 发送消息失败时立即删除自身键。
- `background.js` 收到 `openMd` 后使用 `chrome.alarms` 创建一次性延时清理任务，不使用可能因 MV3 Service Worker 休眠而失效的长 `setTimeout`；`manifest.json` 增加 `alarms` 权限。
- 编辑器每次启动时清扫超过 30 分钟未消费的 `pending:*` 键，并一次性清理旧版本遗留的 `file:*` / `name:*` 键；通过 `?file=<nonce>` 启动时须先排除当前待消费键，避免误删并发打开任务。
- `app.js` 成功加载后按原逻辑删除对应键。

验收标准：

- 模拟发送失败、关闭标签页、跳转失败三种场景后，`chrome.storage.local` 无对应残留键。
- 正常打开流程不受影响，多标签页并发打开不误删。

## 阶段二：v1.7.0 功能实施

### 2.1 最近文件

目标：快速重新打开近期编辑过的本地 Markdown 文件，并尽量恢复直接保存能力。

- 存储：IndexedDB（扩展页面为安全上下文），表 `recent-files`；条目含 `name`、`size`、`lastModified`、`openedAt`，以及 File System Access 句柄或经过校验的本地 Markdown `file://` 地址。
- 通过 File System Access API 打开或保存成功的文件记录句柄；双击关联打开的文件记录 `content.js` 提供的原始 `file://` 地址，但不保存文档正文。兼容 file input 降级路径没有句柄或地址，不进入列表。
- 列表上限 12 条，按最近使用排序；句柄记录使用 `FileSystemFileHandle.isSameEntry()` 去重，关联记录使用规范化后的完整 `file://` 地址去重。
- UI：侧边栏工具区新增紧凑的"最近"菜单，仅在有条目时显示；点击后以浮层列出最多 12 条记录，不长期占用目录区域高度，空状态隐藏。
- 打开行为：句柄记录先 `queryPermission` 再 `requestPermission`（用户手势内）；获得读权限后按内容加载，同时取得写权限则保持 `linked`，否则按 `unlinked` 打开。关联记录在确认扩展仍可访问 `file://` 后重新读取磁盘最新内容，并始终按 `unlinked` 打开。
- 工具内打开、双击关联打开、保存、另存为和带句柄的拖拽打开成功后更新列表。
- 去重优先使用 `FileSystemFileHandle.isSameEntry()`；`name + size + lastModified` 仅作为无句柄时的元数据辅助，不作为保存后的稳定身份。
- 文件已删除、移动或读取权限被拒时给出状态提示并移除条目；关闭“允许访问文件网址”时保留关联记录并提示重新开启。

非目标：不保存文件内容（仅元数据、句柄或本地文件地址）、不做自动保存、不跨设备同步、不引入多文档标签体系。

验收标准：

- 关闭并重新打开扩展后，"最近"列表按使用顺序恢复；工具内打开和双击关联文件均可再次打开。
- 有写权限的文件重新打开后可直接保存；文件被移动/删除时条目被移除且不报错。
- 双击关联记录重新读取磁盘最新内容，并明确提示编辑后保存仍需选择源文件。
- 刷新页面不丢失句柄或关联地址记录。

### 2.2 Mermaid 图表增强

目标：为已渲染图表提供轻量操作能力。

- 每个成功渲染的图块提供操作栏（悬停显示，键盘可聚焦）：下载 SVG、下载 PNG（2x 栅格化）、放大 / 缩小 / 复位（缩放范围 0.5–3）。
- PNG 生成：序列化净化后的 SVG → Blob URL → `Image` → canvas → `toBlob`；栅格化失败时仅保留 SVG 下载。
- PNG 设置最大边长 8192px、最大像素数 32MP；超限时等比降低导出倍率，仍无法生成时回退为仅下载 SVG。
- 下载文件命名 `<文档名>-diagram-<序号>.svg/.png`。
- 缩放通过同步调整 SVG 或内容包装层的实际占位尺寸实现，确保滚动范围随缩放变化；不单独依赖不会改变布局尺寸的 CSS `transform`。
- 缩放只作用于预览中的 SVG（容器内滚动），不改变文档其他部分与 HTML 导出内容；导出仍使用原始净化 SVG，不携带操作栏。
- 未渲染、出错或源码回退的图块不显示操作栏。

非目标：图内节点点击跳转、图表编辑器、图表主题切换、单图拖拽导出到文档。

验收标准：

- 常见图表可下载合法 SVG 与 PNG；宽图缩放后仍可在容器内滚动查看。
- HTML 导出与旧版一致（仅 SVG 内容，无操作栏）。
- 操作栏对键盘可用，下载文件名与当前文档名一致。

### 2.3 Markdown 能力扩展

P1（默认纳入 v1.7.0）：

- 任务列表：引入 `markdown-it-task-lists`，vendor 到 `lib/`；预览复选框只读；样式同时进入 `style.css` 与 HTML 导出模板；Markdown 源码往返不变。
- 脚注：引入 `markdown-it-footnote`；预览与导出支持脚注锚点跳转；净化规则允许所需属性（`id`、`href`、`class` 等）。

P2（先测量，暂不承诺纳入 v1.7.0）：

- 数学公式：引入 KaTeX，支持 `$...$` 与 `$$...$$`；`katex.min.js`、CSS 与字体全部本地化到 `lib/`。
- HTML 导出必须保持自包含：内嵌 KaTeX CSS，字体以 base64 内嵌。
- 体积门槛：产物 ZIP 不超过 3 MB（现状约 1.2 MB）；导出 HTML 的体积增量在实施计划中明确上限。
- 在独立体积实验明确扩展包和单份 HTML 导出的增量后，再决定是否并入 v1.7.0；默认先交付任务列表与脚注。

非目标：完整 GFM 扩展、图表编辑器、代码折叠、编辑器内实时渲染光标处公式。

验收标准：

- 任务列表与脚注在预览、编辑往返、HTML 导出三处行为一致且离线可用。
- 若纳入 KaTeX：文档含数学公式时预览与导出均正确渲染，产物不依赖任何远程资源。

### 2.4 深色模式

目标：在保留当前 GitHub 风格浅色主题的基础上，提供适合夜间阅读与编辑的完整深色主题。

- 模式：提供浅色 / 深色二选一切换，默认保持浅色，不自动跟随系统主题，避免现有用户升级后界面突变。
- UI：侧边栏工具区增加紧凑主题按钮，使用熟悉的明暗图标与悬停提示；切换即时生效，不刷新页面，不挤占目录区域。
- 持久化：主题选择写入 `localStorage`，在同一扩展的多个标签页间同步；刷新和重新打开扩展后保持选择。
- 首屏：新增轻量的前置主题初始化脚本，在主样式加载前设置 `data-theme`，避免页面先亮后暗；脚本保持本地加载并符合 MV3 CSP。
- 样式：以 CSS 变量覆盖页面背景、文字、边框、按钮、侧栏、编辑区、预览区、目录高亮、表格、引用、滚动条、对话框和状态提示，不复制整套组件样式。
- 代码高亮：浅色使用 `github.min.css`，深色使用 `github-dark.min.css`，切换时同步更新高亮主题。
- Mermaid：主题切换后按对应明暗配置重新渲染当前图表；渲染缓存键包含主题，避免复用另一主题的 SVG。
- 图片与普通 SVG 保持原始颜色，不做反色处理。
- HTML 导出保持现有 GitHub 浅色、自包含样式，不受阅读界面主题影响，避免个人显示偏好改变交付文件外观。

非目标：自动跟随系统主题、用户自定义配色、独立编辑区/预览区主题、为导出 HTML 选择主题。

验收标准：

- 浅色与深色之间切换无刷新、无明显闪烁，所有主要控件和状态文字达到清晰可读的对比度。
- 新开标签页、刷新页面和多标签页切换后主题保持一致。
- 代码高亮和 Mermaid 图表随主题正确更新，连续切换不出现旧主题残留或重复渲染错误。
- 目录、滚动条、图片短引用、文件操作、对话框和窄屏布局在两种主题下均可正常使用。
- HTML 导出继续保持浅色且不依赖远程资源。

### 2.5 侧栏信息架构与文档摘要

目标：在不减少能力的前提下压缩操作区占用，让目录继续成为侧栏的主要内容，并让文档统计符合图片短引用、Mermaid 与长文档场景。

- 文档入口：首行保留“打开”“最近”和熟悉的“更多”图标；“新建文档”“导出 HTML”进入更多菜单，菜单不长期占用目录高度。
- 编辑操作：仅在编辑模式显示“保存”“另存为”，与只读浏览入口分层，避免阅读模式出现无关操作。
- 显示设置：字号由循环按钮改为“小 / 中 / 大”分段控件，主题按钮与字号同组；当前选择必须明确并可用键盘操作。
- 目录：继续占据侧栏全部剩余高度并独立滚动；标题数移动到“目录”标题右侧，不再设置独立统计格。
- 文档摘要：取消四格统计卡片，侧栏底部固定显示“字数 · 预计阅读时间”；编辑模式追加行数。
- 统计口径：排除图片 DataURL、图片短引用目标、围栏代码块、Mermaid 源码、行内代码、链接地址和 Markdown 标记；图片替代文字与普通正文保留计数。
- 阅读时间：中文、日文和韩文字符按每分钟 300 字估算，拉丁字母与数字单词按每分钟 200 词估算；空白或极短文档显示“少于 1 分钟”。
- 性能：统计只在内容变化或文档载入时更新，不再由周期任务重复扫描未变化文档。

非目标：自定义统计口径、写作目标、阅读进度记录、更多字号档位、可拖动调整侧栏内部区域。

验收标准：

- 阅读模式常驻两行紧凑操作，编辑模式仅增加一行保存操作；目录区域不因更多菜单长期缩小。
- 字号三档可直接选择，选择状态清晰，刷新后保持，并继续触发 Mermaid 字体适配。
- 空文档、普通长文、含大体积 DataURL 图片及多段 Mermaid 的文档统计稳定，图片编码和图表源码不会放大字数与阅读时间。
- 标题数与实际渲染目录一致；桌面与窄屏下操作、菜单和摘要均不溢出、不遮挡正文。

## 风险与依赖

- 单包化后旧 Lite 用户需手动安装完整包，发布说明中需明确升级路径。
- IndexedDB 中持久化文件句柄依赖浏览器支持；句柄写入失败时功能会安全停用，不影响常规打开与保存。
- KaTeX 会增加包体与导出体积，须在实现计划中先做体积测量。
- 深色模式需要同步处理代码高亮与 Mermaid 缓存；只切换 CSS 变量会产生图表和代码块主题不一致。
